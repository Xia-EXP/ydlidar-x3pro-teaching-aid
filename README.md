# YDLIDAR X3 PRO 雷达教学工具

这是一个面向 Windows + Edge 的本地教学工具。它通过 Web Serial 读取 USB 转串口设备，把 YDLIDAR X3 PRO 的二维测距数据拆成学生可以追踪的步骤：

`串口字节流 -> 协议数据包 -> 一圈扫描 -> 坐标变换 -> 几何障碍簇 / 局部占据证据 / 实验性扫描匹配建图 -> 避障建议与教学渲染`

工具只显示几何避障建议，不控制机器人电机，也不把单雷达点云冒充成人、桌子等语义识别结果。
局部占据图采用 RViz 风格帮助理解射线、空闲区和障碍端点；另提供一个明确标注的“实验性增量建图”模式，用相邻帧扫描匹配估计位姿。它不是完整 SLAM，也不会宣称拥有可靠的机器人轨迹。

## 控制台界面

控制台采用固定深色仪表风格：首屏左侧窄栏集中“设备连接 / 避障决策 / 点位读数”，右侧是占满首屏的“G1 避障仿真”主舞台（与侧栏等高，含复位视角、放大和图例）；其下为通栏、等高并排的极坐标扫描与局部地图，再下方为“参数调整 / 数据诊断 / 教学说明 / 案例视频”页签。“G1 避障仿真”卡用本地打包的 three.js 加载宇树官方 G1 29 自由度模型（`public/models/g1/`，unitree_ros，BSD-3），把每圈雷达点画成从地面到扫描平面的细柱（红=停止距离内、橙=转向距离内、青=更远），地面按左/前/右扇区着色，并让 G1 按当前建议在场景中预演：前进=沿前方走到保留停止距离处，转向=原地转 45° 后前进，停止=原地站定并显示红圈；预演结束后回到雷达位置循环重放，新建议需持续 0.6 秒才切换（停止立即生效）。可拖动旋转视角，“放大”铺满窗口，Escape 退出。它是对同一份几何建议的可视化，不包含真实动力学，也不向任何机器人发送命令；WebGL 或模型不可用时文字建议照常工作。“案例视频”页签收录四段本地短片（`public/media/g1-avoidance.mp4` G1 避障演示，AI 仿真示意；`public/media/g1-slalom.mp4` G1 绕桩行走完整演示，仿真录屏；`public/media/gap-following.mp4` 缝隙跟随法讲解；`public/media/tf-frames.mp4` TF 与坐标讲解），共用一个大播放器，附带按字幕时间整理的章节、0.5× 慢放、循环、本机时间标记和各自的“看前提问 → 对照观看 → 上机复现 → 讨论小结”课堂脚本；“剧场模式”把视频页铺满窗口，Escape 退出；切换到其他页签时视频自动暂停。连接设置、连接排查、扫描图层和地图设置以浮层展开，按 Escape 或点击外部可收起；页签支持方向键、Home 和 End。极坐标图的“当前扫描波束 / 当前包回波 / 已扫扇区”逐包图层默认关闭：雷达约 7 圈/秒，远快于 60Hz 屏幕刷新，逐包绘制会跳动闪烁；关闭时双图只随完整扫描圈重绘，讲解协议时可在“扫描图层”中打开。避障建议卡顶部色条随建议变化（绿=前进、橙=转向、红=停止），同时保留文字徽章。选择实验性建图后显示建图操作与状态，恢复默认会返回局部地图。

宽度 ≤1180px 时主舞台置顶、侧栏三张卡片横排在其下方，≤900px 双图上下排列，≤600px 全部单列。界面已在 1366×768、1920×1080 和 390px 窄屏检查，并通过原有 55 项测试及模拟数据状态验收；不代表实际雷达硬件验收。

## 运行要求

- Windows 10/11。
- 便携发布包内自带 Node.js，无需目标电脑预装 Node 或 npm；仅源码方式启动需要 Node.js 20 或更高版本。
- Microsoft Edge（Web Serial 只在 Chromium 安全上下文中可用）。
- 与雷达匹配的 USB 转接板、驱动和供电。

不要直接双击 `public/index.html`。页面必须由 `localhost` 服务提供，否则浏览器不会开放 Web Serial。

## 启动

### Windows 傻瓜式启动

1. 获取分享的 `YDLIDAR-X3PRO-portable-v0.1.4-win-x64.zip`，完整解压到普通文件夹，不要在压缩包预览窗口里直接运行。适用于 Windows 10/11 x64。
2. 双击 `一键启动.cmd`（或 `one-click-start.cmd`），等待环境自检和 Edge 页面打开。退出时先断开设备，再在命令窗口按 Enter。简明操作见 `使用说明.txt`。
3. 在 Edge 页面点击“选择串口”并授权实际的 COM 口，再点击“连接”。

便携包已经包含官方 Node.js Windows x64 运行时，且发布构建时校验了 Node 官方 SHA-256；目标电脑无需安装 Node、npm 或其他 JavaScript 依赖。首次启动仅访问本机 `127.0.0.1`，不会把雷达数据上传到外网。若电脑没有 Edge，启动器会询问是否通过 Windows `winget` 安装；没有 `winget` 或被学校策略限制时会显示微软官方下载地址。USB 转串口驱动与具体转接板芯片有关，软件无法安全地自行猜测和安装。

从 GitHub **Code → Download ZIP** 得到的是开发源码包，不带 Node 运行时。开发者可先安装 Node.js 20+，再双击 `one-click-start.cmd`；如果 Windows 阻止脚本，也可在 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

双击启动时会自动检查 Node.js 和 Edge，显示 Windows 当前的 COM 口及识别到的 USB 串口候选，并从 5173–5193 中选择可用的本地服务端口。未插雷达也能启动并使用演示功能。发布包优先使用自身的 `runtime/node.exe`，不修改系统 PATH。

在项目目录运行以下命令，可单独查看环境报告，或按需补装缺少的 Node.js 和 Edge。安装完成后重新运行启动器。

```powershell
.\one-click-start.cmd -CheckOnly
.\one-click-start.cmd -Repair
```

启动器不会自动安装 USB 驱动、不会替用户选择 COM 口，也不会自动发送雷达启停命令；这三件事涉及具体转接板和设备安全，必须由使用者确认。

在 PowerShell 中运行：

```powershell
npm test
npm start
```

然后用 Edge 打开 `http://127.0.0.1:5173/`。

课堂使用直接双击 `one-click-start.cmd`。脚本会启动本地服务并打开 Edge；按回车会停止本次脚本启动的服务。

### 发布前检查

维护者可以运行以下命令验证 GitHub 提交是否完整：

```powershell
npm run release:check
npm run release:portable
```

`release:check` 会执行语法检查、55 项协议/几何/建图测试，并启动临时端口检查页面和关键资源。`release:portable` 会下载固定版本的官方 Node.js Windows x64 ZIP、核对官方 SHA-256，再生成便携发布包和 `.sha256` 文件。GitHub Actions 在 push 和 pull request 时执行发布检查。

## 连接雷达

1. 确认 USB 转接板和雷达使用匹配的 5V 供电，不要假设电脑的 3.3V 逻辑口可以给雷达供电。
2. 在页面点击“选择串口”，授权实际的 COM 口。
3. 默认使用 `115200 / 8N1 / 无流控`，这是当前 YDLIDAR SDK 数据表中 X3/X3 Pro 对应的初始配置。
4. 点击“连接”，等待状态变为“正在接收雷达扫描”。
5. 用手或平面物体改变雷达周围环境，观察极坐标图、局部障碍图和扇区决策。

如果设备已供电但没有主动输出数据，可在连接后手动点击“开始扫描”。该按钮发送公开协议中的 `A5 60`，不会在连接时自动发送；“停止扫描”发送 `A5 65`。部分转接板还需要 DTR 控制电机，可在连接前展开“连接设置”并勾选“连接时请求 DTR 电机”。

当前公开 SDK 文档对 X3 Pro 的型号枚举并不完全一致，因此页面不会根据型号号自动猜测配置。若无数据，请依次检查：电源、USB 驱动、COM 口、波特率、转接板接线和雷达是否实际旋转。

### 实验性增量建图

在地图面板的“地图模式”选择“实验性增量建图”，连接并等待实时扫描后点击“开始建图”。第一帧只建立地图原点，之后每一圈使用有限范围的粗到细最近邻扫描匹配估计相对 `X/Y/θ`，再把当前扫描射线写入固定大小的全局栅格。面板会显示当前估计位姿、建图轨迹、匹配质量、内点数、跟踪状态和已累计帧数，并提供“暂停建图”和“清空建图”。

这不是 ROS `gmapping` 或完整 SLAM：本版本没有里程计、IMU、回环闭合、重定位、全局优化或地图文件保存。无里程计的扫描匹配在空旷/对称环境、快速移动、动态人/物体和重复纹理中会漂移或产生重影；匹配质量不足时本帧不会写入地图。应慢速移动，观察“匹配丢失”提示，并在重新摆放雷达后清空建图。全局建图栅格默认 `100 mm / 格`，与固定雷达局部图的分辨率控件分开。

历史建图只用于教学显示，绝不参与前方/左右清距和避障建议。数据过期、串口暂停或切回局部图时，建图会停止累积；地图仍可保留供课堂观察。

## 协议教学要点

默认按 X3/X3 Pro 的无强度三角测距包解析：

- 线上包头：`AA 55`。
- 字段：`CT / LSN / FSA / LSA / CS / Si...`。
- 每个采样 `Si` 为小端序 16 位距离原始值。
- 距离：`Distance(mm) = Si / 4`。
- 起止角：`raw >> 1 / 64` 度，再对包内采样线性插值。
- 三角雷达对非零距离应用二级角度修正。
- `CS` 使用 16 位 XOR 校验。
- `CT & 1` 表示一圈起始包；起始包中的占位采样不作为障碍点。

解析器会处理串口任意分块、粘包、噪声字节、截断包和坏校验包，并在诊断区域显示校验错误和丢弃字节数量。

## 教学界面

模块之间的因果关系和课堂讲解顺序见 [`MODULES.md`](./MODULES.md)。

- **极坐标扫描**：显示当前有效测距点，`0°` 为正前方，正角度向左。
- **局部占据栅格（固定雷达演示）**：用方形栅格区分未知、射线经过的空闲区域和回波端点形成的占据区域，并叠加几何障碍簇和建议方向。
- **实验性增量建图**：用相邻扫描匹配估计位姿，在同一 Canvas 上显示固定大小的全局占据栅格、轨迹、当前位姿和匹配质量。
- **点位内容**：点击扫描点查看角度、距离和 `X/Y` 坐标。
- **数据诊断**：查看扫描频率、点数、数据包、校验错误、丢弃字节和最近原始包。
- **参数实验台**：调整停止距离、转向距离、聚类间距、扇区角度、显示范围、方向校准、栅格分辨率和局部累积时间。

高频串口小块不会直接重绘扫描图：协议解析持续进行，诊断文本最多每 `200 ms` 更新一次，两个 Canvas 只在新的完整扫描或界面配置发生变化时刷新，避免原始数据包速率造成页面抽动。

### RViz 风格局部占据栅格

占据栅格默认使用 `50 mm` 分辨率和 `8 m` 半径，以雷达为中心建立 `lidar_link` 局部坐标系。每个有效回波都会从雷达中心向测量端点投射一条栅格射线：

- 未被近期射线观测的单元保持“未知”。
- 射线经过但尚未到达回波端点的单元增加空闲证据，默认每次 `-1`。
- 回波端点所在单元增加占据证据，默认每次 `+4`。
- 单元证据限制在 `-20` 到 `+20`，避免同一位置永久累积到无法恢复。
- 未持续观测的证据按时间衰减，默认局部记忆窗口为 `3000 ms`，最终回到未知状态。

这种证据分值适合演示“多次观测比单次噪声更可信”，但不是完整的概率占据栅格算法。页面提供“实时射线 / 障碍簇 / 决策”图层开关；关闭图层只改变显示，不改变协议解析、占据证据、聚类和避障规则。避障建议始终只使用最新完整扫描，不使用已经衰减的历史栅格作安全决策。

颜色之外，页面还使用格子明暗、点形、线型、文字图例和状态摘要区分未知、空闲、占据和过期状态，便于投影教学和辅助技术读取。

### 固定雷达限制与建图边界

可靠的局部避障演示仍按“雷达固定在桌面或教具底座上”设计。局部图中雷达始终位于中心，朝向标记只表示 `lidar_link` 的正前方。实验性建图会尝试从相邻扫描推断位姿，但它没有里程计、IMU、外部定位或回环闭合，因此：

- 不能把实验性轨迹当成真实机器人轨迹，也不能把它称为完成了 SLAM。
- 固定雷达局部证据可以稳定演示射线；移动建图只适合慢速、短距离、静态环境的教学观察。
- 如果搬动、旋转或重新接线雷达，应先清空局部栅格和建图，再重新建立第一帧参考。

页面提供“清空局部图”和“清空建图”按钮；断开或更换设备、调整角度偏移、反转左右方向或改变最大显示距离时，会清空旧位姿和地图。停止扫描或数据过期时，已有画面只能作为历史参考，界面会显示暂停/过期状态，并停止给出“前进”建议。

所有局部证据只保存在当前浏览器页面的内存中，不写入磁盘，也不提供录制、导出或回放功能。

### 建议课堂流程

1. 固定雷达和转接板，确认坐标图中的“前、左、右”和实际摆放方向一致。
2. 连接串口后先观察极坐标扫描，让学生找到角度、距离和原始点云之间的关系。
3. 点击“清空局部图”，在雷达前方放置平面物体，比较射线经过的空闲格和端点处逐步增强的占据格。
4. 移走物体，观察旧占据证据在约 3 秒局部记忆窗口内衰减回未知。
5. 分别在前、左、右放置障碍物，对照障碍簇、扇区清距和“前进/左转/右转/停止”建议。
6. 切换到“实验性增量建图”，点击“开始建图”，将雷达以约 `0.1–0.2 m/s` 缓慢沿静态墙/桌角移动，观察轨迹和匹配质量。
7. 暂停建图后移动雷达再继续，说明恢复时会重新建立匹配参考；遇到“匹配丢失”先停下或清空，不要把重影当成真实墙面。
8. 暂停扫描或遮断数据，确认画面明确标记旧数据并撤销可执行的前进建议。
9. 如需演示错误操作，可轻微改变雷达底座方向，观察局部残影和实验轨迹的局限，然后立即清空。

## 测试

```powershell
npm test
```

测试覆盖协议零位包、距离和角度换算、校验失败、错位重同步、任意分块、起始包聚合、坐标转换、跨零聚类、避障规则，以及实验性建图的位姿合成、平移/旋转匹配、低置信拒绝、暂停恢复、边界裁剪和固定路径容量。局部占据模块还验证射线中间格为空闲、端点格为占据、证据上下限、时间衰减、重新配置后的清空和固定大小缓存。

浏览器验收时还应确认：

- `0°` 回波出现在中心正前方，正角度回波出现在左侧。
- 未观测、空闲和占据单元在图例、画面和文字摘要中含义一致。
- 重复观测能增强对应证据，移除障碍后旧证据会按时衰减。
- 图层开关不会改变聚类数量、扇区清距或避障建议。
- 建图模式的历史地图、轨迹和图层开关不会改变当前扫描的避障建议。
- 数据超过 `500 ms`、手动暂停或串口断开时不会继续显示“前进”建议。
- 任何界面和文档都不会把局部残影表述为机器人轨迹或全局 SLAM 地图。

## 安全边界

- 本项目没有机器人电机控制接口。
- “前进/左转/右转/停止”只是基于当前测距的课堂建议。
- 数据超过 500ms 没有更新时，界面会标记旧帧，并停止显示前进建议。
- 局部占据证据、实验性建图和扫描残影不能代替机器人的实时避障传感器融合、安全控制器或制动系统。
- 雷达底座移动、角度配置变化或重新接线后，应清空局部栅格和实验性地图，不能继续信任旧证据。
- 手动停止命令是否让自转模块停下取决于固件和转接板；需要完全断电时请断开 USB 供电。
- 真实设备验收前，以雷达铭牌、转接板说明和实测原始包为准，不要把 X4 的参数直接套用到 X3 Pro。

协议字段依据 YDLIDAR SDK 的公开通信协议文档独立实现；项目不复制厂商 SDK 二进制或原生绑定代码。
